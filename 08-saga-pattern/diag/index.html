🔄 Saga Pattern

Choreography-Based Saga

sequenceDiagram
    participant OS as Order Service
    participant EB as Event Bus
    participant IS as Inventory Service
    participant PS as Payment Service
    participant SS as Shipping Service
    
    OS->>EB: OrderCreated
    EB->>IS: OrderCreated
    IS->>IS: Reserve Stock
    IS->>EB: StockReserved
    
    EB->>PS: StockReserved
    PS->>PS: Process Payment
    PS->>EB: PaymentProcessed
    
    EB->>SS: PaymentProcessed
    SS->>SS: Create Shipment
    SS->>EB: ShipmentCreated
    
    EB->>OS: ShipmentCreated
    OS->>OS: Complete Order
    
    Note over OS,SS: Each service reacts to events independently

Orchestration-Based Saga

sequenceDiagram
    participant C as Client
    participant O as Saga Orchestrator
    participant OS as Order Service
    participant IS as Inventory Service
    participant PS as Payment Service
    participant SS as Shipping Service
    
    C->>O: Create Order
    O->>OS: Create Order
    OS-->>O: Order Created
    
    O->>IS: Reserve Stock
    IS-->>O: Stock Reserved
    
    O->>PS: Process Payment
    PS-->>O: Payment Processed
    
    O->>SS: Create Shipment
    SS-->>O: Shipment Created
    
    O->>OS: Complete Order
    OS-->>O: Order Completed
    
    O-->>C: Order Success
    
    Note over O: Orchestrator controls the flow

Compensation (Rollback) Flow

sequenceDiagram
    participant O as Orchestrator
    participant OS as Order Service
    participant IS as Inventory Service
    participant PS as Payment Service
    
    O->>OS: Create Order
    OS-->>O: ✓ Order Created
    
    O->>IS: Reserve Stock
    IS-->>O: ✓ Stock Reserved
    
    O->>PS: Process Payment
    PS-->>O: ✗ Payment Failed!
    
    Note over O: Start Compensation
    
    rect rgb(239, 68, 68, 0.2)
        O->>IS: Release Stock (Compensate)
        IS-->>O: Stock Released
        
        O->>OS: Cancel Order (Compensate)
        OS-->>O: Order Cancelled
    end
    
    O-->>O: Saga Failed - Rolled Back

Choreography vs Orchestration

flowchart TB
    subgraph Choreography["Choreography 💃"]
        C1[Decentralized]
        C2[Event-driven]
        C3[Loosely coupled]
        C4[Hard to track]
        C5[No single point of failure]
    end
    
    subgraph Orchestration["Orchestration 🎼"]
        O1[Centralized]
        O2[Command-driven]
        O3[Clear workflow]
        O4[Easy to monitor]
        O5[Single coordinator]
    end
    
    subgraph UseWhen["When to Use"]
        U1[Simple flows → Choreography]
        U2[Complex flows → Orchestration]
        U3[Need visibility → Orchestration]
        U4[Max decoupling → Choreography]
    end
    
    Choreography --> U1
    Choreography --> U4
    Orchestration --> U2
    Orchestration --> U3
