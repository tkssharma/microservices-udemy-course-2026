Edge Layer Responsibilities

  • CDN: Cache static assets, images, listing thumbnails (80% of requests)
  • WAF: Block malicious requests, SQL injection, XSS
  • API Gateway: Authentication, rate limiting, request routing
  • Load Balancer: Distribute traffic, health checks, SSL termination

DDD Principles Applied

  • Single Responsibility: Each service owns one business domain
  • Independent Scaling: Search scales 10x more than Booking
  • Separate Deployments: Deploy without affecting other services
  • Database per Service: No shared databases between services
  • API Contracts: Services communicate via well-defined APIs

Auth Architecture Best Practices

  • JWT at Gateway: Validate tokens at edge, not in every service
  • Short-lived Access Tokens: 15 minutes max, use refresh tokens
  • mTLS for Internal: Service mesh handles inter-service auth
  • User Context Propagation: Pass user claims via headers internally
  • Policy Engine: Centralize authorization logic (OPA/Casbin)
  • Audit Logging: Log all auth decisions for compliance

Data Sync Strategy

  • Change Data Capture (CDC): MongoDB Change Streams to Elasticsearch
  • Eventually Consistent: Search index may lag by seconds
  • Denormalization: Search index contains flattened data for speed
  • Read Replicas: Scale reads independently from writes

Search Optimization Techniques

  • Geo-hashing: Convert lat/lng to prefix-searchable strings
  • Denormalization: Store all needed data in one document
  • Availability Bitmap: Pre-compute 365-day availability
  • Ranking & Scoring: Quality score, response rate, booking rate
  • Faceted Search: Pre-aggregated filter counts

Communication Best Practices

  • Service Mesh: Use Istio/Linkerd for mTLS, observability, retries
  • gRPC Internal: 10x faster than REST for service-to-service
  • Schema Registry: Version your events, ensure backward compatibility
  • Circuit Breaker: Fail fast when downstream is unhealthy
  • Retry with Backoff: Exponential backoff for transient failures
  • Dead Letter Queue: Capture failed messages for debugging

Performance Checklist

  • Caching: Cache popular listings, search results for top cities
  • Pagination: Always use cursor-based, never return full dataset
  • Aggregation: BFF (Backend-for-Frontend) reduces round trips
  • Read Replicas: Scale reads independently
  • Connection Pooling: Reuse database connections
  • Compression: gzip responses, especially JSON

Bottlenecks & Solutions

  • Search Latency: Solved with Elasticsearch + Redis caching
  • Double Booking: Solved with distributed locks on availability
  • Payment Failures: Solved with idempotency keys
  • Image Upload: Solved with async processing + CDN
  • Notification Delays: Solved with async event processing

Senior-Level Talking Points

  • Eventual Consistency vs Strong Consistency: Search can be stale, bookings cannot
  • CQRS Pattern: Separate read and write models for different scale requirements
  • Hot Partitions: Popular cities cause uneven load distribution
  • Cache Invalidation: One of the hardest problems - use TTL + events
  • Idempotency: Critical for payment APIs - same request = same result
  • Saga Pattern: Manage distributed transactions with compensating actions
  • Circuit Breaker: Fail fast when downstream service is unhealthy
Designing systems isn't about drawing boxes—it's about understanding scale, trade-offs, and bottlenecks.
