Key Differences

  • Authentication (AuthN): Verifies WHO you are (identity verification)
  • Authorization (AuthZ): Determines WHAT you can access (permission verification)
  • Authentication always comes BEFORE Authorization

Cookie Attributes

  • HttpOnly: Prevents JavaScript access (XSS protection)
  • Secure: Only sent over HTTPS
  • SameSite: CSRF protection (Strict/Lax/None)
  • Domain/Path: Scope of cookie validity

Session Storage Options

  • In-Memory: Fast but not scalable, lost on restart
  • Redis: Fast, scalable, supports expiration
  • Database: Persistent, slower, good for auditing
  • Sticky Sessions: Required for in-memory in load-balanced envs

JWT Pros and Cons

  • Stateless: No server-side session storage needed
  • Scalable: Works great with microservices
  • Cross-domain: Works across different domains
  • Size: Larger than session IDs
  • Revocation: Cannot easily invalidate before expiry

OAuth 2.0 Grant Types

  • Authorization Code: For server-side apps (most secure)
  • Authorization Code + PKCE: For SPAs and mobile apps
  • Client Credentials: For machine-to-machine (M2M)
  • Implicit (deprecated): Was for SPAs, use PKCE instead

OAuth vs OIDC - When to Use What

  • OAuth for API Access: Spotify playlists, GitHub repos, Google Drive files
  • OAuth for Integrations: Slack bots, Zapier, CI/CD pipelines
  • OIDC for Login: When you need user identity (Login with Google)
  • Key Difference: OAuth = Authorization (access), OIDC = Authentication (identity)

SSO Benefits

  • User Experience: One login for all applications
  • Security: Centralized authentication, fewer passwords
  • IT Management: Single point for user provisioning/deprovisioning
  • Protocols: SAML, OIDC, or proprietary solutions

SAML Key Concepts

  • XML-based: Uses XML for assertions (verbose)
  • Browser-based: Works via HTTP redirects/POST
  • Enterprise Standard: Common in corporate environments
  • Metadata: XML files describe SP/IdP configuration
  • Bindings: HTTP-Redirect, HTTP-POST, HTTP-Artifact

OIDC vs OAuth 2.0

  • OAuth 2.0: Authorization only (delegated access)
  • OIDC: Adds authentication (identity verification)
  • ID Token: JWT containing user identity claims
  • UserInfo Endpoint: Additional user attributes
  • Discovery: /.well-known/openid-configuration

Auth Provider Comparison

  • Auth0: Developer-friendly, extensive docs, flexible
  • Okta: Enterprise-focused, workforce identity
  • AWS Cognito: AWS-native, cost-effective for AWS users
  • Firebase Auth: Simple, great for mobile apps
  • Azure AD B2C: Microsoft ecosystem integration
  • Keycloak: Open-source, self-hosted option
