🔍 Search System

🔎 Search Architecture
1

📝 User Query

Location: "Paris", Dates: "Dec 20-25", Guests: 4, Price: $100-300

2

📍 Geocoding

Convert "Paris" to coordinates: lat 48.8566, lng 2.3522

3

🔍 Elasticsearch Query

Geo-distance filter + availability + price range + amenities

4

⚡ Check Availability

Redis bitmap for calendar availability check (O(1) lookup)

5

📊 Ranking & Scoring

ML model ranks results by relevance, quality score, conversion likelihood

6

📋 Return Results

Paginated listings with images, prices, ratings, instant book badge

🗺️ Geo-Search with Elasticsearch

📍 Geo-Distance Query

Find all listings within 10km radius of search coordinates. Uses geo_distance filter.

📊 Faceted Search

Filter by property type, amenities, price buckets. Aggregations for filter counts.

🔤 Autocomplete

Completion suggester for location autocomplete. "Par..." → "Paris, France"

⚡ Caching Strategy

Cache popular searches (Paris, NYC). Redis with TTL for dynamic availability.

⚡ Handling Double Booking
1

🔒 Optimistic Locking

Use version field on reservations. Fail if version changed during transaction.

2

📅 Calendar Locking

Acquire distributed lock on listing+dates using Redis SETNX with expiry.

3

✅ Availability Check

Within lock, verify dates are still available in database.

4

💳 Payment Hold

Authorize (not capture) payment. Reserve funds on guest's card.

5

📝 Create Reservation

Insert reservation record, mark calendar dates as booked.

6

🔓 Release Lock

Release distributed lock. Other requests can now proceed.

💳 Payment Split

👤 Guest Pays

Full amount charged at booking. Funds held in escrow until check-in + 24hrs.

🏠 Host Receives

Payout after guest check-in. Amount minus Airbnb service fee (3%).

🏢 Platform Fee

Guest service fee (14%) + Host fee (3%) = Platform revenue.

🔄 Refund Policy

Flexible, Moderate, Strict policies. Automated refund based on cancellation timing.

📈 Scaling Strategies

⚡ Performance Optimizations

🖼️ Image CDN

CloudFront + S3 for listing images. Responsive images, WebP format, lazy loading.

🔴 Redis Caching

Cache listing data, search results, user sessions. 90% cache hit rate.

🔍 Search Sharding

Elasticsearch sharded by region. Paris listings in EU cluster, NYC in US.

📊 Read Replicas

PostgreSQL replicas for read-heavy search queries. Write to primary only.

🌍 Global Architecture
1

🌐 Multi-Region Deployment

US-East, EU-West, AP-Southeast. Route users to nearest region.

2

🔄 Data Replication

Cross-region replication for disaster recovery. RPO < 1 min.

3

📍 Edge Caching

CDN caches static content at edge. Dynamic content from nearest region.

4

🔍 Regional Search

Search clusters per region. Paris search queries stay in EU.

🗄️ Database Design

📊 Data Models
👤
users
PostgreSQL
  • id, email, phone
  • first_name, last_name
  • avatar_url, bio
  • is_host, is_verified
🏠
listings
PostgreSQL
  • id, host_id, title
  • lat, lng, address
  • price_per_night, max_guests
  • property_type, amenities[]
📅
reservations
PostgreSQL
  • id, listing_id, guest_id
  • check_in, check_out
  • total_price, status
  • created_at, cancelled_at
📅
availability
Redis Bitmap
  • key: listing:{id}:2024
  • bit per day (365 bits)
  • 0 = available, 1 = booked
  • BITCOUNT for range check
🔍 Elasticsearch Index

📍 Geo-Point Field

location: { lat, lon } - Enables geo_distance queries within radius.

🏷️ Keyword Fields

property_type, amenities[] - Exact match filters, aggregations.

📊 Numeric Fields

price, bedrooms, max_guests - Range queries, sorting.

📝 Text Fields

title, description - Full-text search with analyzers.
