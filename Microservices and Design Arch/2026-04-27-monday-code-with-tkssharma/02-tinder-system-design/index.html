💕 Matching Algorithm

🔍 How Matching Works
1

User A Swipes Right on User B

Store: swipes/{userA}/liked/{userB} = true

2

Check Reverse Swipe

Query: Does swipes/{userB}/liked/{userA} exist?

3

If Yes → It's a Match!

Create match record, enable chat, send notifications

4

Publish Match Event

SNS triggers notifications to both users

📍 Geolocation & Discovery

🗺️ Geohashing

Divide world into grid cells. Store user's geohash prefix for fast nearby lookups. Example: "u4pruydqqvj" → London area

📏 Distance Calculation

Haversine formula for accurate distance. Filter by user's max distance preference (1-100 miles)

🔄 Location Updates

Update location when app opens or every 15 mins in background. Batch updates to reduce writes

⚡ Caching Strategy

Cache nearby users in Redis. TTL based on activity. Invalidate on location change

🧠 Recommendation Engine
1

ELO Score System

Each user has a desirability score based on swipe patterns

2

Collaborative Filtering

Users with similar swipe patterns → similar recommendations

3

Active User Boost

Recently active users shown more frequently

4

Diversity Injection

Mix different profile types to avoid echo chambers

📊 Swipe Data Model

📋 DynamoDB Schema

PK: USER#{userId}
SK: SWIPE#{targetId}
Attributes: action, timestamp, location

🔍 GSI for Matching

GSI-PK: TARGET#{targetId}
GSI-SK: USER#{userId}
Enables reverse lookup for match detection

📨 Message Flow
1

User A Sends Message

WebSocket frame: { action: "sendMessage", to: "userB", text: "Hey!" }

2

Lambda Processes

Validate, sanitize, store in DynamoDB with timestamp

3

Find Recipient Connection

Redis lookup: connections/{userB} → connectionId

4

Push to User B

API Gateway Management API → postToConnection

5

If Offline → Push Notification

SNS → Firebase/APNs for mobile push

💾 Message Storage

📋 Messages Table

PK: CONV#{sorted_user_ids}
SK: MSG#{timestamp}
Data: sender, text, read, attachments

🔔 Read Receipts

Update lastRead timestamp per conversation. Send read event via WebSocket to sender

📸 Media Messages

Upload to S3, store URL in message. Generate presigned URLs for viewing

⏰ Message TTL

Optional: Auto-delete messages after X days using DynamoDB TTL

📈 Scaling & Database Design

🗄️ Database Strategy

📊 DynamoDB - Primary

Users: Profiles, preferences
Swipes: Like/Pass records
Matches: Mutual likes
Messages: Chat history

🔴 Redis - Caching

Sessions: Auth tokens
Connections: WebSocket map
Nearby: User feed cache
Rate Limits: Swipe throttling

🔍 ElasticSearch - Geo

Geo Index: User locations
Search: Discovery queries
Filters: Age, distance, gender

📦 S3 - Media

Photos: Profile images
Thumbnails: Resized versions
Chat Media: Shared files

⚡ Scaling Strategies
1

Lambda Auto-Scaling

Concurrent executions scale automatically. Set reserved concurrency for critical paths

2

DynamoDB On-Demand

Auto-scales read/write capacity. Use DAX for microsecond latency reads

3

Redis Cluster

ElastiCache cluster mode for horizontal scaling. Multi-AZ for high availability

4

CloudFront CDN

Edge caching for static assets. Reduce origin load by 90%+

5

Async Processing

SQS for background jobs: notifications, analytics, cleanup

🔐 Security Considerations

🔒 Authentication

Cognito + JWT tokens. Short-lived access tokens, refresh token rotation

🛡️ API Security

Rate limiting, WAF rules, input validation, SQL injection prevention

📍 Privacy

Fuzzy location (not exact). Hide distance when incognito. GDPR compliance

🔍 Content Moderation

Rekognition for image moderation. ML for text toxicity detection

💰 Cost Optimization

⚡ Lambda

Optimize memory allocation. Use Provisioned Concurrency for predictable traffic

🗄️ DynamoDB

Use TTL for old data. Archive to S3 Glacier for compliance

📦 S3

Intelligent Tiering for photos. Lifecycle policies for old media

📊 Monitoring

CloudWatch metrics, X-Ray tracing, Cost Explorer alerts
