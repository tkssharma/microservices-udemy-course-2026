Cache-Aside (Lazy Loading)

Application checks cache first. If miss, queries database and populates cache.

Pros

  • Simple to implement
  • Only cache data that's actually used
  • Cache is always consistent with DB

Cons

  • Three round trips on cache miss
  • Cache stampede on high load
  • Stale data until TTL expires

Read-Through Cache

Cache handles the database query. Application only talks to cache.

Pros

  • Application code is simpler
  • Cache handles all logic
  • Consistent caching behavior

Cons

  • Requires cache library support
  • Cache becomes a dependency
  • Less flexibility in implementation

Pros

  • Data is always consistent

Cons

  • Slower writes (two operations)
  • Higher write latency
  • Cache must be highly available
