🔄 Saga Pattern

Managing Distributed Transactions in Microservices

📚 What is the Saga Pattern?

🎯 Definition

📖 Saga Pattern

A sequence of local transactions where each transaction updates data within a single service. If one step fails, compensating transactions are executed to undo previous changes.

🎯 Purpose

Maintain data consistency across multiple microservices without using distributed ACID transactions (2PC).

⚡ Key Concept

Instead of one big transaction, break it into smaller local transactions with compensating actions for rollback.

🔄 Saga Flow
T1: Create Order
→
T2: Reserve Stock
→
T3: Process Payment
→
T4: Ship Order

Each step is a local transaction. If T3 fails, compensating transactions C2, C1 are executed.

❌ The Problem with Distributed Transactions

🏛️ Traditional ACID Transactions

✅ Works in Monolith

Single database, single transaction. BEGIN → operations → COMMIT/ROLLBACK. Simple and reliable.

❌ Fails in Microservices

Multiple databases, multiple services. Can't lock resources across service boundaries.

🚫 Why 2PC (Two-Phase Commit) Doesn't Work
  • 🔒 Blocking: All participants locked until coordinator decides
  • ⏱️ Latency: Multiple network round-trips add significant delay
  • 💥 Single Point of Failure: If coordinator crashes, all participants stuck
  • 📈 Scalability: Doesn't scale well with many services
  • 🔗 Coupling: Services tightly coupled to transaction coordinator

📢 Event-Driven

🎼 Orchestration-Based Saga

🎭 Central Orchestrator

A dedicated orchestrator service coordinates the saga. It tells each participant what to do and handles the overall flow and compensations.

⏪ Compensating Transactions

🔄 What is Compensation?

↩️ Undo Actions

A compensating transaction undoes the effect of a previous transaction. It's not a rollback — it's a new transaction that semantically reverses the previous one.

📋 Example Compensations

✅ Action: Create Order

↩️ Compensation: Cancel Order

✅ Action: Reserve Stock

↩️ Compensation: Release Stock

✅ Action: Charge Payment

↩️ Compensation: Refund Payment

✅ Action: Ship Order

↩️ Compensation: Recall Shipment / Process Return

🛒 Real-World Example: E-Commerce Order

✅ Happy Path
1. Create Order
2. Reserve Stock
3. Process Payment
4. Ship Order ✅
❌ Failure at Payment → Compensation
1. Create Order ✅
2. Reserve Stock ✅
3. Payment Failed ❌
