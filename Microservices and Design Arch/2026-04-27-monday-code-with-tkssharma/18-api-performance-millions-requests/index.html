🏆 The 10x Performance Formula

1️⃣ Async Everything

Never block the event loop. Use async/await for I/O.

2️⃣ Cache Aggressively

Redis for hot data. CDN for static. In-memory for frequent.

3️⃣ Pool Connections

Database, Redis, HTTP clients - pool them all.

4️⃣ Scale Horizontally

Cluster mode, PM2, K8s - use all CPU cores.

5️⃣ Optimize Queries

Indexes, pagination, projections - fetch only needed.

Protect your API from abuse. Throttle heavy users.

🚨 Top Performance Killers & Fixes

❌ N+1 Queries

1 query → 100 queries. Fix: Eager loading, JOINs

❌ Sync Operations

Blocks event loop. Fix: fs.promises, async/await

❌ No Connection Pool

50ms overhead per request. Fix: TypeORM pool config

❌ Missing Indexes

Full table scans. Fix: CREATE INDEX on WHERE columns

❌ No Caching

Same query 1000x. Fix: Redis + in-memory cache

❌ Large Payloads

Network saturation. Fix: Pagination + field selection

4

Stream large files

Don't load entire files in memory

🔄 Clustering & Horizontal Scaling

🖥️ Single vs Cluster Mode
❌ Single Process
  • 💻 Uses 1 CPU core (12.5% on 8-core)
  • 📉 ~1K req/s max
  • 💀 Single point of failure
✅ Cluster Mode (8 workers)
  • 💻 Uses ALL CPU cores (100%)
  • 📈 ~8K req/s (8x boost!)
  • 🔄 Auto-restart on crash

Node.js Cluster

Built-in. Master forks workers. Manual management.

PM2 (Recommended)

pm2 start app.js -i max. Auto-restart, logs, monitoring.

Docker + Kubernetes

Container orchestration. HPA for auto-scaling.

Load Balancer

Nginx, HAProxy, AWS ALB for multi-server.

🗄️ Database Optimization

🔥 N+1 Query Problem
❌ BAD: N+1 Queries
const users = await User.findAll();
for (const user of users) {
  user.posts = await Post.find({userId: user.id});
  // 👆 1 query per user = N queries!
}
✅ GOOD: Eager Loading
const users = await User.findAll({
  include: [{ model: Post }]
  // 👆 1 query total!
});
⚡ Query Optimization Tips

Add Indexes

CREATE INDEX on WHERE, ORDER BY, JOIN columns

Use EXPLAIN

EXPLAIN ANALYZE to check query plans

Select Only Needed

No SELECT *, specify columns

Cursor Pagination

Use cursor-based, not OFFSET

Batch Operations

Bulk insert/update, not one by one

Read Replicas

Separate read/write for scaling
