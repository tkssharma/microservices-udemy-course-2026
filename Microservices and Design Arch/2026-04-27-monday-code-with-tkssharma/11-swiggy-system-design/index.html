🍔 Swiggy System Design

Food Delivery Platform at Scale

🎯 System Requirements

📋 Functional Requirements
  • 🔍 Search: Search restaurants by name, cuisine, location
  • 📍 Location: Show nearby restaurants based on user location
  • 🛒 Cart & Order: Add items, place orders, track delivery
  • 💳 Payments: Multiple payment options, refunds
  • 🚴 Delivery: Real-time tracking, driver assignment
  • ⭐ Reviews: Rate restaurants and delivery partners
📊 Non-Functional Requirements

📈 High Availability

99.99% uptime. Orders must not fail during peak hours.

⚡ Low Latency

Search < 100ms. Real-time location updates every 3-5 seconds.

📊 Scalability

Handle millions of users, thousands of orders per minute.

🔒 Consistency

Order and payment data must be strongly consistent.

🚧 Technical Challenges

⚡ Key Problems

📍 Real-Time Tracking

WebSocket connections for live updates. Millions of concurrent connections.

🚴 Driver Assignment

Optimal matching considering distance, load, ratings. ML-based allocation.

📈 Peak Load

10x traffic during lunch/dinner. Auto-scaling, circuit breakers.

🗺️ ETA Prediction

Traffic, weather, restaurant prep time. ML models for accurate ETAs.

📈 Scaling Strategies

🚀 How to Scale
  • 💾 Database Sharding: Shard by city/region for geo-distributed data
  • 📦 Caching: Redis for menus, restaurant data, user sessions
  • 📨 Message Queues: Kafka for async processing (notifications, analytics)
  • 🌐 CDN: Static assets, images served from edge locations
  • 🔄 Load Balancing: Distribute traffic across service instances
  • 📊 Read Replicas: Scale reads with database replicas
